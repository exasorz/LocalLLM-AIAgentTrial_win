
# AI開発環境一括自動構築パッケージ (WSL2 + Podman + Ollama)

本パッケージは、Windows環境において既存の開発環境を一切汚さずに、
ボタン一発で最先端のローカルAI開発・エージェント体験環境を完全自動構築するためのインフラ自動化（IaC）キットです。
「AI駆動開発」の迅速な技術展開（プラットフォームエンジニアリング）を目的として設計されています。

---

## 1. 本パッケージの利用目的

* AI駆動開発の早期体験・標準化
次世代のAI駆動開発エージェントやRAG（検索拡張生成）システムをローカル環境に即座に構築し、AIに触れる環境を簡単に構築できます。

* 開発環境のポータビリティ担保と隔離
既存のWSL2環境に影響を与えないよう、完全に隔離された専用のLinuxディストリビューションを自動で切り出します。

* 構築コストのゼロ化
高価なクラウドAIサービスの契約や、オンプレミスの高額なGPUサーバーへの投資を行うことなく、
各自のPCが持つ既存のハードウェア資源（内蔵GPU等）を極限まで引き出して動作させます。

---

## 2. 活用しているコア技術と選定理由

本システムは、低レイヤーのOS設定から最先端のLLMランタイムまでを一本のパイプラインで串刺しにして自動化しています。

* OSラッパー：Windows Batch (SJIS)
ユーザーはバッチを右クリックして「管理者として実行」するだけ。cmd.exeのパース特性を考慮し、最もエラーを起こさないShift-JIS構造を採用。

* OS・仮想化：WSL2 (Ubuntu)
wsl --import 機能を活用し、既存環境を1ミリも汚さない隔離環境（AI-Dev-Env）をバックグラウンドで高速に複製・展開。

* 自動化 (IaC)：Ansible
隔離されたWSL2内部のミドルウェア導入や環境変数設定を「冪等性（何度実行しても同じ状態になる性質）」を保って完全自動化。

* コンテナ：Podman / Podman Compose
ルートレス（非管理者権限）で動作するセキュアなコンテナ基盤。Dockerと互換性を保ちつつ、軽量でポータブルなAIサービス基盤を構築。

* AIランタイム：Ollama
Windows（ホスト）側で動作。Vulkan APIを叩くことで、Intel内蔵GPUや各種グラボのパワーをダイレクトに活用し、LLMを高速化。

* AIモデル：Qwen 3.5 (qwen3.5:2b)
中国のAlibabaが開発した高性能な小型モデルのコード特化モデル。2B（20億パラメータ級）と非常に軽量でありながら、日本語の理解力や指示への追従性が高い。

* UI / 検索基盤：Open WebUI + SearXNG
ChatGPTライクな洗練されたUIと、プライバシー重視の検索エンジンをネットワーク結合。ローカル環境での高精度なWeb検索RAGを実現。

* AIエージェント：Aider
ターミナル上で動作する最強クラスのコーディングエージェント。ローカルLLMと連携し、Gitと連動した自動コード修正・テスト・コミットを自動化。

## 3. 必要条件 (Prerequisites)

本パッケージを実行する前に、以下の条件を満たしているか確認してください。

* OS: Windows 10 または Windows 11 (64bit)
* ストレージ: Cドライブの空き容量が 30 GB 以上 であること（バッチ起動時に自動チェックが走ります）
* グラフィックドライバー: お使いのPCのGPU（Intel HD/Iris Xe Graphics, NVIDIA, AMD等）の公式最新ドライバーがインストールされていること（Vulkanアクセラレーションを有効にするため必須）。
* 権限: スクリプトを実行するWindowsユーザーに「管理者権限」があること。

## 5. 利用手順 (How to Use)

### STEP 1: スクリプトの実行

1. 本パッケージのフォルダをローカル（Cドライブ推奨）に配置します。
2. setup.bat を右クリックし、「管理者として実行」 を選択します。
3. ※WSL2が未有効のPCの場合、OS機能の有効化後にPCの再起動を促されます。再起動後、もう一度同じバッチを「管理者として実行」してください。

### STEP 2: WSL環境の選択（対話）

スクリプトの途中で、以下の選択肢が表示されます。

構築対象となるWSL2環境を選択してください。
[1] 既存のデフォルトWSL環境（Ubuntu等）をそのまま使用する
[2] 既存環境を汚さないよう、新しくAI専用のWSL環境「AI-Dev-Env」を作る

既存環境を保護したい場合は、「2」 を入力してEnterを押してください。バックグラウンドでクリーンな隔離環境が自動生成されます。

### STEP 3: WSL環境の自動構築

選択したWSL2環境に対して、必要なパッケージ、コンテナ、Codex設定をAnsibleで自動構築します。専用環境（AI-Dev-Env）を選んだ場合も、このステップで新規WSL環境の作成から構築まで続けて実行されます。

---

## 6. 構築完了後の使い方

すべての構築が正常に完了すると、画面に完了メッセージが表示されます。

### 🚀 環境の起動方法

PCの再起動後など、環境を起動・利用する際は、用意された起動用バッチファイルを実行してください。
必要な前提条件のチェック（WSLやディストリビューションの存在、Windows上のOllama起動状況）や、WSL内部のコンテナ立ち上げが自動で行われ、そのままWSLターミナルが開きます。

* **デフォルトのWSL環境で構築した場合**: [run_default.bat](file:///c:/Develop/LocalLLM-AIAgentTrial_win/run_default.bat) を実行します。
* **専用環境（AI-Dev-Env）で構築した場合**: [run_AI-DEV-Env.bat](file:///c:/Develop/LocalLLM-AIAgentTrial_win/run_AI-DEV-Env.bat) を実行します。

---

### ① Web UIでのチャット ＆ RAG（ウェブ検索連携）体験

1. ブラウザを開き、 http://localhost:3000 にアクセスします。
2. 初回ログイン（ローカル管理用の任意のアカウント作成）を行います。
3. チャット画面で対話を開始できます。
4. 設定から「ウェブ検索（Web Search）」を有効にすることで、裏で動く SearXNG と連動し、最新のネット情報を踏まえた回答（RAG）を完全ローカルで体験できます。

### ② ターミナルでのAIエージェント駆動開発体験

WSL2（AI-Dev-Env）の内部には、コーディングエージェント Aider が自動インストールされ、Ollamaと環境変数が紐付けられています。

1. WSL2のターミナルを起動します（隔離環境を作成した場合は wsl -d AI-Dev-Env）。
2. ご自身のGit管理された開発プロジェクトのディレクトリに移動します。
(例: cd /home/user/projects/my-app)
3. エージェントを起動します。
コマンド: aider
4. ターミナル上の対話欄で、日本語で「〇〇の関数を追加して、テストコードも書いてコミットして」と指示を出すだけで、AIエージェントによる自動コード生成・修正が開始されます。

## 7. トラブルシューティング

* 文字化けや不審なエラーが発生する
本バッチファイルは「Shift-JIS(ANSI)」形式での保存を前提としています。コードを編集する際は、文字コードがUTF-8に変わってしまわないよう注意し、必ずShift-JISで上書き保存してください。

* AIの回答（生成）が極端に遅い
Windowsのタスクマネージャーを開き、AI動作中に「GPU」の項目が動いているか確認してください。もしCPUが100%になってしまっている場合は、グラフィックドライバーが古い可能性があります。最新の公式ドライバーをインストールし、PCを再起動してから再試行してください。

* WSLのメモリ消費が激しい
WSL2はデフォルトの状態だと、Windowsの物理メモリを最大70%〜80%近くまで際限なく消費し、ホスト（Windows）側の動作を圧迫する仕様になっています。
各自のPC環境（ブラウザや他の業務ツール）を快適に保つため、以下の設定を強く推奨します。

1. Windows側で `Win + R` キーを押し、 `notepad %USERPROFILE%\.wslconfig` と入力してEnterを押します。
2. メモ帳が開いたら（白紙、または既存の設定がある状態）、以下の内容を貼り付けて上書き保存します。

```ini
[wsl2]
# WSL2に割り当てる最大メモリ量を制限（PCの総メモリに合わせて4GB〜8GB等に調整）
memory=4GB

# 必要に応じてスワップ領域（仮想メモリ）のサイズも制限
swap=2GB

```

3. 設定を反映させるため、WindowsのコマンドプロンプトまたはPowerShellを開き、以下のコマンドを実行してWSL2を一度完全にシャットダウンします。
```cmd
wsl --shutdown

```

4. 再度 `setup.bat` を実行するか、WSL環境を起動すると、メモリ消費量が指定した上限（4GB）でピタッと固定されるようになります。

> **💡 テクニカルヒント（メモリの一発全解放）**
> AIを使った検証作業を終え、しばらくコンテナやエージェントを使わない場合は、Windows側で `wsl --shutdown` を実行するだけで、WSL2が占有していた数GBのメモリをいつでも一瞬でWindows側に完全返却（解放）させることができます。
